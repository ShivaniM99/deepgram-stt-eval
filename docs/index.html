Is Deepgram good enough for a pharmacy refill line?

A pre-launch evaluation of Deepgram Nova‑3 on 648 audio clips — synthetic, real-voice, and silence. It is accurate enough and it never invents words. Two things about how you connect it would still have caused harm.

Hear the failures

Every clip below is synthesized, so you can regenerate all of it from the repository. Press play, then read what came back.

1. The same audio. One config change. A different real drug.

Telephone-quality audio, Australian English voice. Nothing about the audio changes between these two rows — only whether a keyterm list was attached.

actually said
I'm calling about cyclosporine 100 milligrams. My date of birth is August nineteenth, nineteen forty one.
no keyterm list
I'm calling about cyclosporine one hundred milligrams. My date of birth is 08/19/1941.
half a keyterm list
I'm calling about cycloserine one hundred milligrams. My date of birth is 08/19/1941.

Cycloserine is a real, dispensable tuberculosis drug. The sentence is fluent and well-formed, so nothing downstream rejects it. Adding a partial keyterm list caused this; with no list the same audio transcribed correctly.

2. The same words, degraded down to a phone line

Indian English voice, identical utterance, rendered at studio quality and then through an 8 kHz G.711 telephone channel.

clean 16 kHz
I'd like a refill on amiodarone two hundred milligrams. Prescription number 3562773.
telephone 8 kHz
I'd like a refill on Ami order on two hundred milligrams. Prescription number 3562773.
+ half keyterm list
I'd like a refill on amlodipine. On two hundred milligrams. Prescription number 3562773.

"Ami order on" is obvious nonsense — a human would catch it. "Amlodipine" is a blood-pressure medication, and nobody catches that. The prescription number survived every condition.

Synthesized hold music. Some systems invent plausible sentences out of this, which on a pharmacy line means a refill request with no patient behind it.

Nothing returned — on all 24 non-speech clips, in all three configurations. Silence, dial tone, keypad beeps, line hiss, crosstalk and music. This is a genuine strength.

What would fix it

  • Read the drug name back and require confirmation. The 98% threshold is only defensible because such a step exists; without it the bar must be higher.
  • Buffer transcript segments; never act on one. Accumulate consecutive finals and use UtteranceEnd to decide a caller has finished.
  • Use the complete formulary in the keyterm list, or none of it.
  • Route low-confidence drug names to a person rather than accepting a wrong one.

What this does not establish

  • No real pharmacy call audio. That is protected health information. The real-voice set is 16 clips in one voice — enough to show a problem exists, not to size it.
  • Two assumptions were wrong in the same direction. The synthetic tier turned out harder than real speech on word error rate and easier on fragmentation. It is a stress test, not a proxy for real callers.
  • Latency is client-observed from one machine, inclusive of network round trip. Three earlier definitions of this metric were discarded as meaningless against the live API; one returned negative three seconds.
  • Single-turn only. No barge-in, multi-turn state or tool calling — the Voice Agent API is out of scope here.
